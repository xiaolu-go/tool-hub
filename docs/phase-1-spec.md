# tool-hub 第一期需求、页面与验收标准

版本：v1.2 · 更新日期：2026-11-04 · 状态：第一期已实现并完成验证

已按用户指定的目录结构组织项目。计算规则与示例独立于 [calculation-rules.md](calculation-rules.md)，实际进度记录于 [implementation-plan.md](implementation-plan.md)，设计决策记录于 [decisions.md](decisions.md)。

## 1. 产品定位与目标

tool-hub 是一个网页版个人工具集，当前主要服务于养老金规划测算。用户通过设定存入计划、开始领取年份、领取计划和假设收益率，观察资金在未来各年的变化，并比较不同假设方案。

第一期交付两个部分：

1. 可继续添加工具的工具集框架与卡片式首页。
2. 第一个可完整使用的工具：资金计算器，页面名称为“养老金资金计算器”。

第一期希望帮助用户回答：

- 每年存入一笔钱，连续存入若干年，到开始领取时预计有多少资金？
- 每年领取固定金额，可以足额领取多少年？
- 按指定年数领取后，还剩多少资金，是否出现领取缺口？
- 相同存入和领取条件下，不同假设收益率带来的差异是什么？

本工具输出的是按用户假设计算的资金变化，不直接输出“推荐购买某产品”等结论。

| 事项 | 第一期默认约定 |

| 初始余额 | 测算起始年份年初、首笔存入前余额为 0 |

| 领取方式 | 每年年末领取，目标金额固定 |

| 公共条件 | 两个方案共用存入计划与领取计划，仅名称和收益率独立 |

| 最大测算跨度 | 从起始年份起最多 120 个自然年，包含起始年份 |
| 金额单位 | 人民币元，精确到分 |
| 数据保存 | 当前浏览器本地保存最近一组成功测算的输入 |

余额不足时支付最后一笔剩余金额，是处理资金耗尽的规则；用户主动设置提前领取或自定义部分领取仍属于后续范围。

## 4. 用户流程与页面结构

### 4.1 主流程

打开首页 → 进入养老金资金计算器 → 填写公共计划 → 设置两个方案收益率 → 点击“开始测算” → 查看汇总、图表和年度明细 → 修改参数后重新测算或导出结果。

### 4.2 页面与导航

本期采用 Hash 路由，逻辑路径如下；实际地址包含 `#`。

| 逻辑路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 工具首页 | 展示全部已注册工具 |
| `/tools/pension-calculator` | 养老金资金计算器 | 第一个正式工具 |
| 其他路径 | 未找到页面 | 提供返回首页入口 |

浏览器前进、后退、刷新和直接打开计算器地址均应正常工作。具体静态部署平台在后续开发或部署时确定。

### 4.3 首页

- 页头显示项目名“tool-hub”，副标题可用“个人工具集 · 养老金规划与资金测算”。
- 工具卡片包含稳定标识、名称、简述、图标、状态与入口。
- “养老金资金计算器”卡片状态为“可使用”。
- “收支规划”卡片状态为“规划中”，不使用伪装成可用入口的点击反馈。
- 本期不增加搜索、分类筛选、收藏和用户中心。

### 4.4 计算器页面

按以下顺序组织：

1. 标题、简要用途和返回首页入口。
2. 共同计划设置：按年份或按年龄，两列紧凑输入，存入和领取只填写一组。
3. 两行方案设置：每行仅名称与假设年收益率。
4. 存入、等待、领取阶段时间线。
5. “开始测算”“恢复默认”操作。
6. 结果汇总和方案比较。
7. 图表。
8. 年度明细与导出操作。
9. 可展开的计算规则说明。

宽屏可将参数和结果分栏；窄屏按上述顺序纵向排列。参数和结果区必须有清晰边界。


## 5. 输入参数与校验

### 5.1 公共计划

| 参数 | 含义 | 默认值 | 校验 |
| --- | --- | --- | --- |
| 测算起始年份 | 第一笔存入所在年份 | 首次打开时的用户本地年份 | 1900～2200 的整数 |
| 每年存入金额 | 存入期内每年年初投入的金额 | 10,000.00 元 | 大于 0，最多两位小数，上限 1,000,000,000.00 元 |
| 存入年数 | 连续存入多少年 | 10 年 | 1～100 的整数 |
| 开始领取年份 | 第一次年末领取所在年份 | 默认起始年份 + 20 | 必须晚于最后存入年份，且不超过最大测算年份 |
| 每年计划领取金额 | 领取期内每年希望领取的金额 | 12,000.00 元 | 大于 0，最多两位小数，上限 1,000,000,000.00 元 |
| 领取模式 | 指定年数或领至耗尽 | 指定年数 | 两种模式单选 |
| 计划领取年数 | 包含首次领取年份在内的领取年数 | 20 年 | 指定年数模式必填，1～120 的整数，结束年份不能超过测算上限 |

派生信息：

- 最后存入年份 = 起始年份 + 存入年数 − 1。
- 等待年数 = 开始领取年份 − 最后存入年份 − 1。
- 指定年数模式的结束年份 = 开始领取年份 + 计划领取年数 − 1。
- 最大测算年份 = 起始年份 + 119。
- 存入计划总额 = 每年存入金额 × 存入年数。

例如：2030 年开始存入，存入 10 年，最后存入年份为 2039 年；如果 2040 年开始领取，等待年数为 0，第一笔领取发生在 2040 年年末。

用户修改起始年份或存入年数后，不静默修改已经填写的开始领取年份；如果出现冲突，显示关联校验错误。恢复默认时才按当前本地年份重新生成整组默认值。

从本地恢复的起始年份保持保存值，不因跨年自动改动。

### 5.1.1 按年龄规划（2026-11-04 新增）

两个方案共用一套计划。在“按年份 / 按年龄”中选择一种，界面只显示当前方式的时间字段，年度金额与存入年数始终共用。

| 参数 | 默认值 | 规则 |
| --- | --- | --- |
| 开始存入年龄 | 35 岁 | 0～104 的整数 |
| 存入年数 | 与年份模式共用，默认 10 年 | 1～100，最后存入年龄必须小于开始领取年龄 |
| 开始领取年龄 | 60 岁 | 1～105 的整数，须晚于最后存入年龄 |
| 领取结束年龄 | 85 岁 | 不小于开始领取年龄，最高 105 岁，包含当年领取 |

按年龄不需要填写当前年份、出生日期或计划领取年数。计划领取年数自动计算为“结束年龄 − 开始领取年龄 + 1”，使用固定结束计划，即使资金提前耗尽也列出到结束年龄的缺口。年份模式继续支持指定年数与领至耗尽。

按年龄是整岁假设，每增加一岁代表一个年度资金周期，不按生日或自然年份换算。图表横轴、时间线、汇总、耗尽及不足额事件、年度明细和 CSV 都明确显示年龄口径。每次切换方式使旧结果进入待更新状态。

两个方案的名称与收益率采用紧凑两行排列，不重复展示整套计划。默认保持按年份，避免误读已保存的旧年份计划；旧数据可迁移恢复。

### 5.2 方案参数

| 参数 | 默认值 | 规则 |
| --- | --- | --- |
| 方案 A 名称 | 银行假设方案 | 去除首尾空格后 1～30 个字符 |
| 方案 B 名称 | 保险假设方案 | 去除首尾空格后 1～30 个字符 |
| 方案 A 假设年收益率 | 2% | −100%～100%，最多四位小数 |
| 方案 B 假设年收益率 | 3% | −100%～100%，最多四位小数 |

两个方案使用稳定的内部标识 A、B。名称相同时仍以“方案 A / 方案 B”区分。

默认收益率仅用于演示交互，不代表当前银行利率、保险收益、保证收益或推荐值。页面在收益率输入区展示一句简短说明即可。

界面输入 `2` 表示 2%，计算时转换为 0.02，不能将 2 直接作为收益率乘数。负收益率表示年度亏损假设。

### 5.3 校验与状态反馈

- 空值、非数字、非有限值、超出精度、超出范围、年份冲突，都显示字段旁的中文错误。
- 不把空输入自动解释为 0，不静默截断小数，不自动交换冲突年份。
- 点击“开始测算”时校验整组输入；无效时保留用户输入并定位首个错误。
- 修改任一参数后，旧结果标记“参数已修改，请重新测算”，导出暂不可用。
- 新测算失败时不覆盖上次成功结果；旧结果继续保持“待更新”状态。
- 成功测算后，表格、图表、汇总和导出统一绑定这一组已提交参数。
- 首次进入使用默认参数，但先显示“设置参数后开始测算”；有效保存数据恢复后可以自动重算。
- 恢复默认会清除本工具保存的测算参数，填入默认值并清空结果；操作前进行一次简短确认。


## 6. 年度计算规则

以 [计算规则文档第 6 节](calculation-rules.md#6-年度计算规则) 为准。

## 7. 结果展示要求

### 7.1 时间线

显示存入期、等待期、领取期的年份或年龄范围；等待为 0 时明确显示“无等待期”。

领至耗尽模式尚未测算时，领取阶段显示“开始年份—耗尽或测算上限”；测算成功后可补充本次实际时间轴终点。

### 7.2 汇总区

公共信息展示：存入计划总额、最后存入年份、开始领取年份、等待年数、领取模式、本次测算年份范围。

两个方案并列展示：

- 方案名称与假设收益率。
- 首次领取前资金。
- 累计存入、累计领取、累计收益。
- 期末余额。
- 足额领取年数与有领取年数。
- 耗尽状态、首次不足额年份。

指定年数模式额外展示累计领取缺口，以及“计划全部足额完成”或“计划存在缺口”。领至耗尽模式不把另一方案继续计算期间的零领取年累加为用户承诺的总缺口。

### 7.3 图表

| 图表 | 横轴 | 纵轴 | 内容 |
| --- | --- | --- | --- |
| 年末余额对比 | 自然年份 | 金额 | 两个方案年末余额折线 |
| 年度实际领取对比 | 自然年份 | 金额 | 两个方案实际领取柱形图及计划领取参考线 |

- 图例包含方案名称与 A/B 标识，颜色在所有结果中保持一致。
- 年份或年龄轴范围一致，必要时减少标签密度；年龄刻度标明“岁”。
- 提示框显示年份、阶段、方案、精确金额。
- 余额曲线用直线连接年度观测点，避免平滑插值造成额外含义。
- 金额轴可以使用万元、亿元等缩写，但须标明单位；精确金额仍可在表格中读取。
- 不仅依靠红绿颜色表达状态，增加文字、图例或线型。
- 图表异常时，汇总和年度明细仍应可用。

### 7.4 年度明细

用方案 A / 方案 B 切换查看，同步年份范围，并固定显示方案名称。

必备列：年份或年龄、阶段、年初余额、当年存入、当年收益、计划领取、实际领取、领取缺口、年末余额、累计存入、累计领取、累计收益。

桌面端提供清晰表头；手机端允许表格区域横向滚动，页面主体不能因此整体横向溢出。本期最多 120 行/方案，不增加分页与虚拟滚动。

### 7.5 CSV 导出

- 一次导出两个方案完整年度明细，按年份、方案 A/B 排序。
- 每行包含方案标识、方案名称、假设收益率和上述明细字段。
- 文件补充可复现的公共参数列：起始年份、每年存入金额、存入年数、开始领取年份、每年计划领取金额、领取模式、指定领取年数、本次测算结束年份。
- 金额使用两位小数的纯数字文本，不带千分位、货币符号或“万元”。
- 表头为中文，采用 UTF-8 BOM 编码；正确处理逗号、引号和换行。
- 对用户输入的方案名称做电子表格公式注入防护。
- 文件名包含 tool-hub、养老金测算和本地导出日期时间。
- CSV 只导出成功测算的结果快照；参数待更新时不能导出旧结果冒充新结果。


## 8. 本地保存与恢复

- 保存键固定为 `tool-hub:pension-calculator:v1`。
- 保存内容包含存储结构版本、模型规则版本、保存时间和最近成功测算的输入（含时间方式与年龄设置）。模型版本 2 支持迁移原版本 1 的年份方案。
- 两个方案的稳定标识、名称与收益率，以及全部公共参数均应保存。
- 不持久化年度结果；恢复时按已保存输入重新计算。
- 只有输入通过完整校验并测算成功后才替换保存内容。
- 不保存无效输入、临时输入或待更新状态；刷新后恢复的是最近成功测算的输入。
- 存储读取失败、数据损坏、版本不支持时，回退到默认输入，并提示“已保存的数据无法恢复，请重新设置”。
- 存储不可用或写入失败时，仍能完成测算和导出，提示“本次设置未能保存到浏览器”。
- 恢复默认只处理本工具的保存键，不清除其他工具的数据。
- 参数和计算结果不主动上传，不引入埋点或第三方分析脚本。
- 页面用简短说明提示“设置保存在当前浏览器，清理浏览器数据后可能丢失”。

| 样式 | CSS Modules + CSS 自定义属性 | 统一视觉变量与组件样式 |
| 图表 | Apache ECharts | 年度折线与领取对比图 |
| 金额运算 | decimal.js，独立配置 64 位有效数字与明确舍入方式 | 十进制金额计算 |
| 测试 | Vitest | 计算引擎、参数校验与数据恢复测试 |
| 状态 | React 本地状态 | 区分编辑草稿与成功结果快照 |
| 保存 | 浏览器 localStorage | 最近成功测算参数 |
| 依赖管理 | npm 与单一锁文件 | 固定实际安装版本 |

这是本项目选择的实施方案。框架、路由、图表、金额库与测试工具的具体用法，在开发时按各自官方资料核对，参考入口见第 14 节。

开始开发时核对依赖的稳定版本与运行环境兼容性，并在锁文件和 README 记录实际版本；本文不预先写死“最新版”版本号。不同时引入第二套路由、状态、图表或金额库。

### 9.2 模块职责

| 建议位置 | 职责 |
| --- | --- |
| `src/app/` | 应用入口、统一布局、路由 |
| `src/app/App.tsx` | 首页与未找到页面 |
| `src/features/registry.ts` | 工具元信息、状态与入口配置 |
| `src/features/pension-calculator/` | 计算器表单、结果编排和工具内组件 |
| `src/features/pension-calculator/domain/` | 参数定义、校验、年度计算、汇总与比较 |
| `src/components/` | 已实际复用的卡片、字段、按钮等 |
| `src/lib/` | 本地保存、CSV、金额展示等通用辅助能力 |
| `src/styles/` | 全局基础样式与视觉变量 |
| `docs/` | 需求、模型与开发说明 |

上述为模块职责约定，按实际实现维护。

计算规则必须独立于 React、图表和浏览器存储。相同的规范化输入必须产生相同结果；计算模块不能自行读取当前年份、浏览器状态或界面值。

图表、表格、汇总和导出消费同一份结果，不分别实现资金公式。首页新增工具以添加注册项和对应工具模块为主，不把所有工具业务堆入首页。

桌面版复用主要依靠计算模块与界面边界；第一期不为桌面端建立额外适配层或启动桌面工程。

### 9.3 数据契约

| 对象 | 必须包含的信息 |
| --- | --- |
| 工具元信息 | 稳定 id、名称、描述、图标、可用状态、逻辑路径 |
| 公共计划 | 起始年份、年度存入金额、存入年数、开始领取年份、年度计划领取金额、领取模式、指定领取年数 |
| 方案输入 | 稳定 id A/B、显示名称、百分比形式的年收益率 |
| 年度记录 | 方案 id、年份、阶段、第 7.4 节全部年度字段 |
| 方案汇总 | 第 6.7 节指标、状态、指定模式下的累计缺口 |
| 比较结果 | 公共起止年份、输入快照、两组年度记录与汇总、差额、是否触及上限 |
| 保存封套 | 存储版本、模型版本、保存时间、输入 |

金额在输入规范化、结果、保存与 CSV 边界上均用不带格式符的十进制字符串表示；收益率以百分比十进制字符串保存，避免百分数与小数混淆。运算时转换为 Decimal，不通过浮点数中转。

状态至少区分：未测算、有效结果、输入已修改、输入无效。方案终止状态至少区分：计划结束、资金已耗尽、达到上限仍未耗尽。


## 10. 视觉与交互基线

- 使用简体中文，以养老金规划的清晰阅读和操作为优先。
- 浅色背景、卡片区域、清晰数字层级；不制作复杂装饰和动画。
- 页面品牌保持 tool-hub，计算器副标题说明其用途。
- 金额输入标明“元”，收益率输入标明“%”，年份和年数不混用。
- 金额结果使用千分位和两位小数，负收益保留负号。
- 重点状态用“已耗尽”“计划存在缺口”“截至上限尚未耗尽”等文字表达。
- 对“收益率”“首次领取前资金”“足额领取年数”等提供简短就地说明。
- 规则说明明确年初存入、年末领取、固定收益率及未计入的因素。
- 输入具有可见标签，键盘可操作，错误文本关联对应字段，焦点状态清晰。
- 以约 375px 手机宽度和 1440px 桌面宽度验证主要流程。
