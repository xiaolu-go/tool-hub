# 重要设计决策

记录日期：2026-11-04。仅记录会影响后续实现和维护的选择。

## D-001：采用用户指定的 features 目录

业务按 `src/features/<tool>/` 组织，取代原稿的 `src/tools/`。工具注册表为 `src/features/registry.ts`，首页和路由共用。应用入口与首页暂放在 `src/app/`，不额外创建空页面目录。

## D-002：前端静态应用与 Hash 路由

第一期不需要后端。使用 React、TypeScript、Vite 与 React Router 的 Hash 路由，构建使用相对资源路径。静态托管部署时不要求服务端处理业务路由。没有接入账户或云端数据服务。

## D-003：年度现金流与独立金额模块

年初存入、年末领取。仅年度收益舍入到分，再向下一年结转。decimal.js 使用独立实例、64 位有效数字、ROUND_HALF_UP；输入输出边界使用十进制字符串。完整规则与可复算数值以 `calculation-rules.md` 为准。

## D-004：共同时间轴与“首次不足额”

两个方案独立计算余额，共用起止年份。指定年数模式始终显示完整计划；领至耗尽模式在两方案均耗尽且至少计算到首次领取年时结束，否则最多 120 年。耗尽较早的方案会继续显示零余额，首次不足额年份仅基于共同时间轴已计算到的年份，不推断未生成年度。

## D-005：结果快照、保存与恢复

编辑草稿与成功结果分开。参数有任何编辑即标记待更新，禁用导出；只有成功提交才更新结果与保存。只保存最近成功输入，不保存结果或草稿。恢复时校验版本与参数后重算。恢复默认使用确认对话框，且仅清除本工具的保存键。

## D-006：图表渐进加载

计算器页和图表分开按需加载。ECharts 仅注册所需图表和组件，使用 SVG 渲染、ResizeObserver 调整尺寸。图表提示采用富文本渲染而非用户字符串拼接 HTML；图表不可用时仍提供汇总与表格。坐标可近似，提示与表格从精确结果读取金额。

## D-007：文档拆分与原稿保留

本期需求维护在 `phase-1-spec.md`，计算维护在 `calculation-rules.md`，进度维护在 `implementation-plan.md`。两个正文保留原章节编号以兼容相互引用。最初综合文档归档在 `archive/`，仅供历史参考。

## D-008：保留远端初始化记录

本地项目关联用户指定的 `xiaolu-go/tool-hub` 仓库，基于远端 main 分支开始工作，保留已有的 MIT LICENSE。版本记录不重建、不强制推送；远端发布另行按用户指令执行。

## D-009：保留可重复运行的浏览器验证

增加 Playwright 作为开发依赖，以本机浏览器验证生产产物。配置包含桌面与手机两种视口，测试与截图放在 `tests/browser/` 和忽略版本管理的 `test-results/`。不引入额外云端测试服务。


## D-010：共用精简表单与年龄规划

2026-11-04 用户要求精简输入并支持年龄方式。合并共同计划，采用两列输入；每个方案仅一行名称与利率。按年龄保留存入年数以表达存完后的等待期，不引入额外结束存入年龄输入。

年龄方式输入开始存入、开始领取和结束领取年龄，最高 105 岁。包含结束年龄当年的年末领取，模式自动规范化为固定计划；自然年份模式仍支持领至耗尽。计算引擎复用年度坐标并用 timeBasis 区分，所有用户可见结果和 CSV 必须使用对应单位。

模型版本提升到 2，保存键和存储封套版本保持不变；读取版本 1 时补充 year 方式后校验重算。年龄恢复后的未使用年份字段不虚构映射，用户切回按年份时才按当前本地年补充默认值，原结果标为待更新。未使用方式的字段不做业务校验。
